## Fixes made during the live check

- **7ab09da** — after a regeneration the new `VM_Source` stamp is written onto the project's types
  (`GeneratedFamilyStore.WriteStamp`): a reload with `overwriteParameterValues = false` keeps the old
  stamp, so the next run with the previous points was reported "reused" on the new shape (item 3).
- **Guard fix (this commit)** — `FamilyNaming.Decide`: `--replace` regenerates before the same-spec
  shortcut (item 13: that is the only way a hand-edited family gets its generated shape back). A
  reused family is still not opened (speed: no `EditFamily` per `lwall`), so the response now says
  "reused, not regenerated" and, for a straight run, compares Revit's volume with profile area ×
  length: a >1 % difference adds `WARN: volume … but the profile gives … — the loaded family differs
  from what VibeModel generated (edited in Revit?). Add --replace to regenerate it.` (skipped when the
  element was joined — a join may have cut it). Re-run of item 13 after the redeploy: see the
  "Re-check" section.
